# UC08: Code-mixed quick-commerce orders and search

**Business question.** A kirana delivery service, a quick-commerce app or a D2C brand receives orders on WhatsApp,
typed the way Indians actually type them: "bhaiyaa 1kg tamater 1/2 kg adrak nahi 250gm adrak…, cod, 110059". Can a
model turn these messages into a correct structured order? Can it write product, place and customer names in native
script (for invoices, delivery labels and search)?

## Task A: order extraction

There are 100 hand-authored messages: 86 orders and 14 search/availability questions. They cover:

- romanised Hindi, Tamil, Bengali, Marathi and Kannada
- native-script Hindi, Tamil, Bengali, Marathi and Kannada, including Bengali/Devanagari/Kannada digits in pincodes
- Indian English and Hinglish

They include typos (tomrw, mrng, Gud morning), corrections ("1/2 kg adrak nahi 250gm"), negation ("bendekayi
beda" means *don't* want okra), history that must be ignored ("2 kg pyaaz bheje the kal, aaj 1 kg aur"), brand names,
local units (kilo, darjan, gaddi, kattu, pisvya, ta) and payment slang (GPay, PhonePe, Paytm, nakad, cash e debo).

The model receives an 80-item catalog and must output JSON:
`{items:[{name, brand, qty, unit}], pincode, payment: COD|UPI|card, slot}`.
The slot is `today|tomorrow` + `morning|afternoon|evening|night`, or `asap`. The prompt fixes the clock at
Sunday 11 Oct 2026, 10:00.

Systems: `sarvam-105b` (thinking off and on), `gemini-3.8-flash` (thinking off), `sarvam-30b-local`,
`qwen3-30b-local`.
Cloud comparators: `openai:gpt-5.4-mini` and `or:anthropic/claude-haiku-5.5` (thinking off, full sets). The frontier ceiling, `gemini-pro-latest`, `openai:gpt-5.5` and `or:anthropic/claude-sonnet-5.5` (thinking on), runs on a fixed 30-message and 30-name subset: every item whose index % 10 is 0, 3 or 6. The 3 sarvam-105b-think replies that came back empty at max_tokens 6000 are rerun at 16000 and reported as `sarvam-105b-think(16k cap)`.
The local models are scored on every other message (50) and every other name (50) because the shared llama-server ran at about 2 min per order. The "50-message subset" and "50-name subset" metrics compare all systems on the same inputs.

Metrics:

- **Item F1 (strict).** An item counts only if the catalog name, the brand and the quantity are all right. Units
  are normalised: g↔kg, ml↔l, and dozen = 12 count. All pack units (packet, bottle, piece…) count as the same unit.
  Where a message states both a count and a size ("Tata salt 1kg x2"), either reading is accepted.
  Brand matching is case- and punctuation-insensitive substring matching, so "Amul" matches "Amul Gold", and
  aliases such as Coca-Cola|Coke are accepted.
- **Item F1 (name only).** Did it identify the right products?
- **Exact whole-order accuracy.** Every item strictly right, no extra items, and pincode, payment and slot all
  right. This is the number that decides whether a human has to touch the order.
- **Pincode, payment and slot accuracy, and JSON validity rate.** Each is a fraction of messages.

## Task B: transliteration

There are 100 romanised names, 25 each in Hindi, Tamil, Bengali and Marathi. They are well-known places,
person-style names and regional brands (Aavin, Pothys, Chitale Bandhu, Gokul). The gold is the standard
native-script spelling. Common accepted variants are listed, such as मुंबई/मुम्बई and லட்சுமி/லக்ஷ்மி.
The Marathi gold deliberately uses Marathi orthography: लोणावळा, कोल्हापूर, गोकुळ. A Hindi-style spelling
counts as wrong.

Systems: Sarvam `/transliterate` (en-IN → xx-IN), `sarvam-105b`, `gemini-3.8-flash` and the local models.
Metrics: exact match after NFC normalisation and ZWJ/ZWNJ removal, and CER against the closest accepted
spelling.

## Data

The data is in `data/uc08_quick_commerce/orders.json` and `translit.json`, generated by `build_data.py`, which
also validates them. It is **synthetic**: written by hand for this benchmark, with no real customer messages,
names or addresses. Pincodes are real area codes, used only as format examples. Licence CC-BY 4.0.

## How to run

```bash
.venv/bin/python suites/uc08_quick_commerce/build_data.py
.venv/bin/python suites/uc08_quick_commerce/run.py api      # API systems, then score
.venv/bin/python suites/uc08_quick_commerce/run.py local    # local models
.venv/bin/python suites/uc08_quick_commerce/run.py score
```

Raw calls are stored in `results/raw/uc08_quick_commerce.jsonl`. A rerun skips calls that already succeeded.

## Caveats

There is one author and 100 messages per task, so CIs are wide (about ±8 points on accuracy). Some golds involve
judgement calls, such as "1 kg sorsher tel" (kg is kept, l is accepted) and "aaj raat tak" (night). These cases
are listed in `build_data.py` so anyone can disagree in the open.

Disclosure: four Bengali transliteration golds gained accepted variants *after* the first outputs were
inspected. These are native surname forms (Bose → বসু, Chatterjee → চট্টোপাধ্যায়), অরিজিত beside অরিজিৎ, and
ঋতুপর্ণ because "Rituparna" is used for both genders. Before the change, exact match was Sarvam /transliterate 84%,
sarvam-105b 88% and gemini 98%.
